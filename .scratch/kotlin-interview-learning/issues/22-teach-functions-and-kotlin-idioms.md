# 22: Teach functions and Kotlin idioms

**What to build:** Publish a complete functions-and-idioms group that helps a Java developer design readable Kotlin APIs with lambdas, extensions, receivers, scope functions, and inlining while recognizing when an idiom obscures intent.

**Blocked by:** 21: Teach collections and sequences

**Status:** ready-for-agent

- [ ] The group covers lambdas, higher-order functions, extension functions, scope functions, receivers, inline functions, non-local returns where relevant, and reified type parameters.
- [ ] Scope-function teaching emphasizes receiver/result differences and decision guidance rather than memorizing names.
- [ ] Extensions are explained as statically resolved functions rather than true member mutation or inheritance.
- [ ] Inline and reified lessons distinguish source semantics, bytecode consequences, performance claims, and API constraints.
- [ ] Verified examples exercise receiver resolution, lambda behavior, inline control flow, reified access, and common ambiguity or readability mistakes.
- [ ] Java comparisons use functional interfaces, lambdas, utility methods, and static helpers only where useful.
- [ ] Focused questions and the group scenario require designing and defending a readable higher-order or extension API.
- [ ] A human reviewer approves pedagogy, sources, interview realism, and implementation-detail wording before concepts become verified.
- [ ] The complete group is navigable, searchable, assessable, progress-aware, and green under the release command.
