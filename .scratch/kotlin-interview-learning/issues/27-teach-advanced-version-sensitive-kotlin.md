# 27: Teach advanced and version-sensitive Kotlin

**What to build:** Complete the searchable curriculum with advanced features that earn their complexity, making stability and version boundaries explicit so uncommon tools do not burden the core path or masquerade as timeless language guarantees.

**Blocked by:** 26: Teach asynchronous streams and concurrency

**Status:** ready-for-agent

- [ ] The group covers contracts, reflection, annotations, DSL construction, and selected Kotlin 2.4 features justified by backend or interview value.
- [ ] Each topic is classified as core, deep dive, or reference according to frequency, semantic importance, design consequences, and version sensitivity.
- [ ] Experimental APIs or compiler options are locally marked with required opt-ins and are excluded from claims about stable baseline behavior.
- [ ] Lessons distinguish specification guarantees, documented library contracts, compiler behavior, and incidental implementation details.
- [ ] Verified examples use the pinned baseline and label behavior that would differ under another Kotlin, JDK, or coroutine version.
- [ ] Advanced nodes remain searchable and connected without crowding the default core graph or curated main path.
- [ ] Focused questions and the group scenario require explaining when a specialized feature earns its complexity and naming its constraints.
- [ ] A human reviewer approves pedagogy, primary sources, interview realism, stability labels, and version wording before concepts become verified.
- [ ] The complete group is navigable, searchable, assessable, progress-aware, and green under the release command.
