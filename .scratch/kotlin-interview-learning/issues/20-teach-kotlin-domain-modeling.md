# 20: Teach Kotlin domain modeling

**What to build:** Publish a complete domain-modeling group that helps a senior Java developer choose deliberately among Kotlin's classes and modeling constructs based on semantics, invariants, generated behavior, and API design.

**Blocked by:** 19: Teach the Kotlin type system and null safety

**Status:** ready-for-agent

- [ ] The group covers data classes, sealed hierarchies, enums, objects, companion objects, value classes, delegation, and immutability.
- [ ] Concept boundaries avoid turning every syntax form or convenience into a separate graph node.
- [ ] Lessons distinguish source-level convenience from generated JVM shape and identify equality, copying, boxing, initialization, and exhaustiveness consequences where relevant.
- [ ] Java comparisons focus on records, class hierarchies, statics, wrappers, and delegation only where they sharpen Kotlin choices.
- [ ] Verified examples exercise representative generated behavior, exhaustive modeling, invalid assumptions, and mixed Java-facing APIs when relevant.
- [ ] Prerequisites, related edges, categories, depth, and curated order connect cleanly to the completed type-system group.
- [ ] Focused interview questions and the group scenario require choosing among modeling alternatives and defending trade-offs.
- [ ] A human reviewer approves pedagogy, sources, interview realism, and guarantee-versus-implementation wording before concepts become verified.
- [ ] The complete group is navigable, searchable, assessable, progress-aware, and green under the release command.
